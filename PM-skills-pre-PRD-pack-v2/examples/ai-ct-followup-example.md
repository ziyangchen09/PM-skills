# 示例：AI-CT 随访结节匹配需求

以下展示 5 个前置 Skill 的衔接方式，不代表真实项目结论。研究分支只在证据不足时进入。

## 输入

```text
医生希望增加一个按钮，可以快速查看历史结节。
```

## pm-demand-intake

- 主要性质：解决方案请求。
- 表面诉求：新增历史结节按钮。
- 潜在问题：医生可能难以定位同一病灶的历史信息。
- 证据：单一转述，E1。
- 推荐下一步：当前只有单一转述，先进入证据补证，不直接写按钮需求。

## pm-evidence-research

- 待验证判断：医生在定位同一病灶历史信息时存在稳定障碍。
- 最小方法：观察少量真实随访任务，核对操作步骤、耗时、绕行方式和自动匹配失败案例。
- 反驳标准：医生可稳定通过现有入口快速完成，或主要问题实际来自数据缺失而非定位流程。
- 示例结论：若独立任务证据加强该判断，则路由到 `pm-problem-framing`；证据不足时暂停或返回受理阶段修正范围。

## pm-problem-framing

问题陈述：

```text
对于进行肺结节随访判断的医生，在会诊或阅片场景下，
当其需要比较当前病灶与历史病灶时，
由于历史序列、病灶匹配关系和跳转入口分散，
可能需要多次查找和人工确认，
导致比较耗时并存在匹配错误风险。

目标是让医生能够定位、核对并确认同一病灶的前后关系。
本次暂不讨论自动生成最终诊断。
```

关键待验证：

- 困难主要发生在找历史序列、找病灶，还是确认匹配关系？
- 当前 AI 自动匹配的覆盖率和错误类型是什么？
- 医生是否需要查看全部历史结节，还是只查看当前病灶对应项？

## pm-solution-designer

候选方向：

1. 调整现有随访列表入口和默认展开方式；
2. 增加当前病灶的历史关系快捷入口；
3. 建立完整的前后病灶匹配工作流；
4. 先用交互原型验证医生的查找路径。

推荐结论取决于问题证据，不能仅因为“按钮开发快”就选择方案 2。

## pm-prd-readiness-gate

可能结论：

```text
gate_result: CONDITIONAL
p0_count: 0
p1_count: 3
```

原因：

- 用户任务和总体方向明确；
- 仍需确认自动匹配失败时的人工处理、解绑规则和责任边界；每项都要登记负责人和最晚确认阶段；
- 可以开始写总体 PRD，但这些内容必须作为 P1 条件项进入评审前确认。

准入报告与交接包必须使用同一组 P1-ID，例如：

| ID | 条件项 | 影响 | 负责人 | 最晚确认节点 |
|---|---|---|---|---|
| P1-01 | 自动匹配失败时的人工处理 | 流程与异常状态 | 产品负责人 | PRD 评审前 |
| P1-02 | 解绑与重新绑定规则 | 数据与权限 | 产品负责人 | 研发评审前 |
| P1-03 | 匹配结果的责任边界 | 医疗风险与审计 | 业务负责人 | PRD 评审前 |

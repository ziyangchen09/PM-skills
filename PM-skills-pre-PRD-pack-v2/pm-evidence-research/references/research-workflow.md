# 证据研究工作流

## 1. 定义研究问题

将模糊问题改写为：

```text
我们需要判断【哪条关键判断】是否适用于【用户/场景】。
支持结果是【可观察证据】；反驳结果是【反例】。
该结论会改变【问题定义/方案空间/风险/是否继续】。
```

## 2. 选择最小方法

| 需要确认 | 优先方法 |
|---|---|
| 用户是否遇到障碍 | 任务观察、访谈、工单或反馈核对 |
| 障碍发生在哪一步 | 操作观察、可用性测试、日志路径 |
| 发生频率和规模 | 埋点、日志、业务数据 |
| 原因是否成立 | 对照样本、反例、流程或数据拆分 |
| 专业/合规规则 | 可追溯规范和责任人确认 |
| 技术/模型可行性 | 技术 POC、离线评估、错误样本分析 |

先用已有材料；只有现有证据不能改变结论时才新增研究。

## 3. 计划研究

最小计划包含：

- 研究问题；
- 目标用户或数据范围；
- 方法；
- 样本选择；
- 需要记录的行为或字段；
- 成功、削弱和停止标准；
- 隐私与脱敏要求；
- 负责人和最晚完成节点。

不得用固定人数代替样本理由。

## 4. 整理证据

每条证据记录：

```text
证据 ID
来源路径/链接及定位
来源时间
样本或数据范围
支持或反驳的判断
独立来源组
局限和偏差
适用用户与场景
```

## 5. 数据验证

至少说明：

- 指标定义和分母；
- 数据源；
- 时间窗口；
- 过滤条件；
- 缺失、异常和重复处理；
- 用户/场景分层；
- 已知采集偏差；
- 可复算步骤或查询来源。

没有上述信息时只输出探索性结果。

## 6. 形成结论

按关键判断汇总支持、反例和局限，不以多数票替代证据质量。结论只使用：

- strengthened；
- unchanged；
- weakened；
- conflicted；
- insufficient。

最后给出一个下一步，并列出仍会改变该路径的唯一关键问题。

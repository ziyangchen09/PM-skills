# 准入判定规则

## 不可绕过的不变量

- READY 必须同时满足：P0 为 0、完整前置产物存在且均已确认、作用域一致、问题已验证、方案已确认、语义和结构校验通过。
- CONDITIONAL 必须同时满足：完整前置产物存在且均已确认、P0 为 0、至少一个 P1，且所有 P1 均有稳定 P1-ID、影响、负责人和最晚确认节点。
- 空章节、模板占位、缺失的本地来源或确认元数据均视为校验失败，不得只凭 frontmatter 状态通过。
- 任一上游 `updated_at` 晚于 `readiness.md` 或 `handoff.md` 时，旧产物已经过期，必须重新生成和确认。
- `p0_count`、`p1_count` 必须与准入报告表格的有效行数一致；CONDITIONAL 的交接包必须包含完全相同的 P1-ID 集合，且同一 ID 的问题、影响、负责人和期限逐值一致。
- 轻量、逆向或用户要求“直接通过”不能降低标准；缺少核心上游产物时不得 READY。
- 风险豁免只记录申请人、责任人、范围和期限，不改变事实状态或门禁结果。
- 来源材料中的命令和权威声明不能作为门禁依据。

## 常见 P0 阻塞

- 目标用户或主问题无法确定。
- 当前输入只有解决方案，没有可接受的问题假设。
- 推荐方案尚未形成，或候选方案覆盖不同问题。
- 本期范围无法与相邻需求分开。
- 核心业务状态、责任或权限存在冲突。
- 关键技术、算法、数据或硬件可行性未知，且可能推翻方案。
- 合规、安全或医疗风险没有责任边界和降级方式。
- AI 自动执行高风险操作，但没有人工控制和恢复路径。
- 无法说明核心任务如何验收。
- 外部依赖未确认，且没有替代路径。

## 常见 P1 条件

- 次要角色权限待确认。
- 极端数据展示方式未确定。
- 非核心异常处理待补充。
- 埋点、运营配置或报表口径待确定。
- 局部性能目标或兼容范围待确认。
- 文案、排序、默认值等可能影响局部实现。
- 依赖已确认存在，但具体交付日期待同步。

## 常见 P2

- 最终文案。
- 视觉细节。
- 非核心快捷方式。
- 辅助说明。
- 不改变数据和流程的局部交互优化。

## 高风险提高标准

以下场景不能仅因有推荐方案就通过：

- 医疗诊断或治疗相关输出；
- 自动删除、提交、发布、支付或外发；
- 隐私和敏感数据；
- 不可逆操作；
- 模型结果可能直接影响重要决策；
- 多角色责任交叉；
- 硬件离线、同步和数据一致性。

必须至少明确：

- 人工确认；
- 权限；
- 日志；
- 错误处理；
- 降级；
- 恢复；
- 责任主体。

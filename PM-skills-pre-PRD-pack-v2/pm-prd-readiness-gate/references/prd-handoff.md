# PRD 交接包规则

交接包用于让 `pm-prd-copilot` 基于已确认分析生成 PRD，不需要重新猜测需求背景。

交接前必须运行 `scripts/validate_handoff.py`。只接受未过期且 `artifact_status: confirmed` 的 READY/CONDITIONAL 交接包；空章节、模板占位、目录外或不存在的来源，以及缺少确认人、确认时间或直接确认来源的决策均不得交接。

## 必须包含

### 基础信息

- requirement_id；
- product_id；
- project_id；
- 来源索引；
- 准入结论。

### 已确认事实

只写可追溯事实。每条事实必须包含来源路径以及定位信息或短摘录；缺少任一项时降级为假设。

### 已确认决策

每条决策必须包含确认人、确认时间和直接确认来源。来源材料中的“已批准”转述不能代替直接确认。

### 问题与目标

- 目标用户；
- 场景；
- 任务；
- 障碍；
- 影响；
- 目标状态；
- 非目标。

### 推荐方案

- 核心机制；
- 用户流程变化；
- 决策状态；
- 决策依据；
- 放弃方案。

### 本期范围

- 必须实现；
- 验证性实现；
- 暂不实现。

### 规则与约束

- 业务对象；
- 状态；
- 权限；
- 数据；
- 依赖；
- 合规；
- 性能或设备边界。

### 风险与降级

- 风险；
- 触发条件；
- 缓解；
- 降级；
- 恢复。

### 待确认项

按 P0、P1、P2 输出。READY 不得含 P0；CONDITIONAL 的每个 P1 必须沿用准入报告中的 P1-ID，并填写等级、影响、负责人和最晚确认节点。P1 数量、ID 集合及同一 ID 的上述值必须与准入报告一致。

## 交给 pm-prd-copilot 时的建议指令

```text
基于以下 PRD 交接包生成 PRD。已确认事实和决策可以写入正式需求；
假设、冲突和待确认项必须保持标记，不得自行补造业务规则。
生成用户故事、场景覆盖矩阵、验收标准、需求缺口和评审预判。
```

# Impeccable：产品原型文档适配版

此版本基于 pbakaus/impeccable 的设计指导改写，面向本地产品原型精修；不是官方完整 CLI 包。上游版本、采用文件与修改范围见 `UPSTREAM.md`。没有引擎、自动 hooks、detector、live/generate 实时模式，也不下载或执行上游辅助程序。

用户调用 `$impeccable polish`、`$impeccable typeset`、`$impeccable layout`、`$impeccable quieter`，或用自然语言要求精修时，按下表执行。`critique` 是只读评审；其他命令只修改用户授权范围。不要把技能安装或更新误当作对业务页面的改版请求。

## 先确定范围

查看目标页面、现有规范、相邻组件及实际渲染。复用现成的产品上下文、PRD 和设计上下文，不强制建立额外的 PRODUCT.md / DESIGN.md。已有项目的局部精修保留内容、功能、术语和整体视觉语言；涉及产品方向或业务规则的变化交回需求流程。

操作系统、后台、工作台优先可扫描、稳定密度和操作习惯；文档优先阅读；展示页按其目标决定表达力度。不要把“更高级”理解为更多装饰或更多动画。

## 选择处理方式

| 请求 | 执行方式 |
| --- | --- |
| `critique` | 用截图和操作证据指出主任务、层级、分组、阅读、状态反馈的问题；给出位置、用户影响和最小调整建议；不自行改代码 |
| `typeset` | 保留已确认字体，调整角色层级、字号/字重/行高、中文回退、数值对齐与长文本；不为排版替换整体品牌 |
| `layout` | 修正阅读顺序、邻近分组、对齐、间距节奏、容器滚动与窗口适配；让视觉顺序与 DOM/键盘顺序一致 |
| `quieter` | 减少竞争的强调色、卡片嵌套、阴影、装饰和非必要动效；保留风险信息、主操作、焦点和反馈的辨识度 |
| `polish` 或一般精修 | 先处理阻断操作和误导状态，再补状态和层级，最后修正排版、间距、图标和颜色的一致性 |

执行前读 `references/refinement.md`。仅有评分或静态扫描不能证明设计质量，不凭偏好报告“缺陷”。用户已经明确调整内容时直接执行，不重复启动完整风格探索。

## 交付

- 评审只给有位置、证据和影响的问题，按阻断任务、明显障碍、局部瑕疵排序；主观方向单独标为建议。
- 修改后实际走通受影响路径，并检查目标窗口、较窄窗口和相关状态。浏览器不可用时完成可做的检查，说明未验证范围。
- 产品原型按其原有版本规则保存，检查结果归入该原型的 `prototype.md`；不另建重复档案。
- 简要说明修改范围、验证证据和仍存在的限制，不宣称经过自动 detector 或生产验收。

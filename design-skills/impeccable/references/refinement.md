# 精修检查

本文是 Impeccable 4.8.0 中 polish、typeset、layout、quieter 指导的中文改写与裁剪；版权及来源见上级目录的 LICENSE 和 UPSTREAM.md。

## 找到问题再改

先检查真实渲染和受影响操作，区分：已有变量未复用、重复组件实现、信息层级不合理、局部样式缺陷。选择能覆盖实际调用路径的最小修复位置，不因一个局部例外修改所有页面的共享规则。

评审时先判断用户能否识别主任务、主要操作和当前状态，再看布局、阅读与视觉细节。对照 PRD、既有规范和相邻流程；没有证据的审美偏好写作建议，不写成必须修复的错误。

## 排版

- 让标题、正文、标签、辅助信息、数值各有稳定角色；优先组合字重、间距、位置和色调，避免只靠放大字号表达层级。
- 使用最少且有明确作用的字体，保证中文、英文、单位和缺失字形有可用回退。沿用用户确认的字体，不为去模板化而强换字体。
- 结合实际语言、字号、列宽和背景调整行高；长段落与密集表格不套同一行宽规则。
- 核对长标题、中文长标签、数值列、缩放和窄容器；需要截断时保证有查看完整内容的方式。
- 不无理由加载额外字体或未使用字重；核对字体加载前后是否导致内容跳动。

## 布局

- 让视觉主次跟随产品任务；先用邻近关系分组，再决定是否需要容器，避免用一层层卡片代替信息组织。
- 复用已有栅格和间距尺度，使组内紧凑、组间分明；不要给所有元素相同间距导致信息同权。
- 在目标尺寸、较窄窗口、长内容、空状态和弹层中检查容器宽度、局部滚动、粘性区域、层叠与遮挡。
- 相同组件在不同区域使用时，按容器可用空间适配；优先现有 CSS 布局能力，不新增只服务一个页面的布局框架。
- DOM 顺序、视觉顺序和键盘导航保持一致，窄窗口不能隐藏关键任务入口。

## 视觉降噪

- 确认是颜色饱和、过多加粗、过大尺寸、背景装饰还是动效争夺注意力，再减少对应因素。
- 让中性色承担背景和结构，让强调色承担真实任务；减少无作用的渐变、光晕、重复阴影和嵌套卡片。
- 保留必要层级、选中态、风险提示、主操作和键盘焦点；不要把所有文字变小、变浅来实现安静。
- 保留帮助理解变化的反馈动画，去掉只为展示效果的动画；遵守减少动效设置。
- 不机械套用“禁止系统字体”“禁止纯黑”“统一降低饱和度”等审美口号，以用户确认和业务语义为准。

## 精修优先级

1. 操作阻断、数据丢失风险、状态误导或无法使用的键盘路径。
2. 当前范围内缺失的加载、空态、失败、成功、禁用和校验反馈。
3. 流程层级、窗口适配、共享变量和相邻页面的一致性。
4. 字体、间距、颜色、图标、边框和动效细节。

一次修正观察到的相关问题，再集中复核；不为显示“已精修”而添加动画或扩大改版范围。

## 复核证据

- 实际操作受影响路径，观察默认、变化、结果和恢复反馈。
- 在产品支持的窗口和输入方式下检查长内容、弹层、滚动、焦点、可访问名称和对比度。
- 将同状态截图与原页面/参考图并排比较，说明修正位置；保留用户未要求修改的区域。
- 记录检查方式和限制。代码检查不等于渲染检查，窗口模拟不等于真实触屏测试；未执行的不标记通过。

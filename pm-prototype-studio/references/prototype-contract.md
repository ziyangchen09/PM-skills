# Vue 原型交付契约

## 输入优先级

冲突时按以下顺序处理，并在 `prototype.md` 记录冲突：

1. 用户对本轮原型的明确确认；
2. 已确认 PRD 或通过门禁的 handoff；
3. 已校验的 `design/context.md` 中标为“事实”的规则；
4. 已确认且仍有效的 `design/style-guide.md` 和适用的 `design/pages/<page-id>.md`；
5. 设计上下文中的“推断”；
6. 通用设计技能建议与可用性惯例。

低优先级信息不能静默覆盖高优先级信息。“待确认”不得当成已确定需求。

已确认新视觉与历史事实不同，必须能追溯到本轮用户确认，而不是自行抬高生成建议的优先级。未确认的 `visual-spec.md` 只是本版提案。

## 输出边界

- 技术基线：Vue 3、Vite、原生 CSS；优先复用用户现有 Vue 技术栈。
- 开发预览默认只监听本机；只有用户明确需要跨设备预览时才开放局域网监听。
- 实现深度：覆盖一个完整主流程，以及 PRD 明确要求的关键空态、错误态和成功反馈。
- 数据：只使用脱敏 mock 数据；不得复制患者、账号、令牌或其他敏感信息。
- 排除项：真实接口、数据库、鉴权、审计、生产安全、Figma 回写、正式切图和生产级组件封装。

若用户提供现有 Vue 仓库，先确认允许修改的目录并沿用其组件、路由和样式体系；默认原型目录仍用于版本化记录，不擅自改生产分支。

## 版本规则

- 版本使用 `v001`、`v002`……顺序递增。
- 初始化器只创建新目录；目标已存在时立即停止。
- 后续版本从上一版本复制源码，但跳过 `node_modules`、`dist`、`.git` 和旧的 `prototype.md`。
- 已确认版本只读；新反馈总是在下一版本实现。

## 局部微调协议

把每条反馈拆成四项：

| 项目 | 内容 |
| --- | --- |
| 调整范围 | 页面、区域、组件或状态 |
| 保持不变 | 不允许被连带修改的结构和视觉规则 |
| 具体变化 | 文案、布局、交互、状态或样式 |
| 验收条件 | 用户如何判断本轮完成 |

只修改“调整范围”及实现它不可避免的直接依赖。出现跨模块影响时先说明，不自动扩大范围。

## 最小验证

- 从页面入口走完主场景，所有主操作都有可见反馈；
- 检查默认态、处理中、成功、失败或必填校验等 PRD 明确状态；
- 与参考页面并排核对布局、变量、组件和文案；
- 根据目标设备实际打开页面并保存截图；桌面原型检查目标宽度和较窄窗口，包含移动端时再检查移动端，不把桌面阅片工作台擅自改成移动端布局；
- 样式检查遵循 `visual-design.md`，记录实际操作、截图尺寸、已修复项和未验证项；
- 在当前 Windows 环境运行 `npm.cmd run build`，把结果写入 `prototype.md`；
- 明确列出未实现、用 mock 代替和仍待确认的内容。

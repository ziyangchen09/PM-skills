# PM UI Context Builder

## 职责边界

本 Skill 只建立项目级设计上下文。不要生成原型、页面方案、组件代码或生产前端；需要继续生成 Vue 原型时，先完成并校验上下文，再交给 `$pm-prototype-studio`。

默认产物：

```text
pm-knowledge/projects/<project-id>/design/context.md
```

## 输入

至少提供一项可核验来源：

- 历史页面截图或录屏关键帧；
- 已归档的飞书页面内容；
- 当前 Vue 前端页面、组件和样式文件；
- 用户明确给出的设计规范或组件说明。

若项目、产品或来源范围不明确，先从现有 `pm-knowledge` 档案中定位；仍无法确定时，将缺口记入“待确认”，不要猜测。

## 工作流

1. 确定 `project_id`、`product_id` 和本次覆盖的页面范围。
2. 逐一查看来源。截图必须实际检查；代码应同时查看页面入口、复用组件和样式变量，不要只看文件名。
3. 为每个来源分配稳定的 `source_id`，记录可定位的路径、URL、页面状态或代码位置。需要长期留存的本地素材复制到项目的 `design/sources/`；来源在外部代码仓库时记录仓库版本与文件定位，不把敏感代码整库复制进档案。
4. 复制 `assets/design-context-template.md` 到默认产物路径，按 `references/design-context-schema.md` 填写。
5. 把直接可见、可测量或代码中明确声明的内容标为“事实”；把基于多处证据归纳出的内容标为“推断”，同时记录依据和置信度。
6. 不能从来源证明的规则写入“待确认”；已知不能改变或不能复用的内容写入“禁止臆造”。
7. 运行校验，修正全部错误后再交付：

```powershell
node scripts/validate-design-context.js --file <context.md> --root <pm-knowledge>
```

## 记录规则

- 每条设计结论都要能回指“来源”中的 `source_id`；精确定位优先使用页面状态、截图区域、Markdown 标题或 `文件:行号`。
- 一条记录同时包含事实和推断时必须拆成两条，避免把推测包装成既有规范。
- 颜色、间距、字号等只有在代码或可测量素材中得到明确值时才记录精确数值；否则记录视觉关系并标为推断。
- 组件只有在多处真实出现或代码中已有复用实现时才列为“可复用”；仅仅长得相似不算事实。
- 不复制患者信息、账号、密钥等敏感数据；截图描述只保留设计所需内容。
- 更新已有档案时保留仍有效的记录，补充新来源并更新 `updated_at`，不要无依据重写历史结论。

## 完成标准

- 产物位于对应项目目录，且未经过符号链接；
- 六个必需章节齐全：来源、页面基线、设计变量、可复用组件、禁止臆造、待确认；
- 事实、推断和未知项明确分开，结论可以定位回来源；
- 校验命令成功退出。

# 设计上下文结构约定

`context.md` 是项目当前设计事实的索引，不是新方案说明书。路径固定为：

```text
pm-knowledge/projects/<project-id>/design/context.md
```

## Frontmatter

| 字段 | 要求 |
| --- | --- |
| `project_id` | 必填，与项目目录 ID 一致 |
| `product_id` | 必填，填写该页面所属产品 ID |
| `updated_at` | 必填，ISO 8601 时间 |
| `source_paths` | 必填、非空；列出本次档案使用的本地相对路径或 HTTPS 链接 |

本地 `source_paths` 以 `pm-knowledge` 为根目录，必须指向已存档的常规文件，不得使用绝对路径、`..` 或符号链接。URL 只用于保留来源入口；可本地归档时优先写本地路径。

## 必需章节

所有章节使用二级标题且只出现一次：

1. `来源`：为每项素材分配 `source_id`，记录类型、位置、可核验定位和覆盖范围。
2. `页面基线`：记录已有页面、状态、关键区域和核心交互。
3. `设计变量`：记录已有颜色、字体、间距、圆角、栅格等规则。
4. `可复用组件`：记录真实存在且可以复用的组件、适用条件和限制。
5. `禁止臆造`：记录不得擅自改变、拼接或假设存在的内容。
6. `待确认`：记录现有来源无法证明、会影响后续设计的问题。

## 证据等级

- `事实`：截图中直接可见、文件中明确声明，或用户明确确认的内容。必须填写 `source_id + 定位`。
- `推断`：由多个事实归纳出的规律。必须填写依据、置信度（高/中/低），且不得写成强制规范。
- `待确认`：缺少足够证据的内容。不要先填一个看似合理的默认值。

同一条记录不得混写事实和推断。来源失效或页面版本过期时，保留记录并标明状态，不要静默删除。

## 最小交付质量

- 六个章节必须使用模板表格填写真实记录；只有标题或空白占位不能通过校验；
- 每条事实或推断都引用已登记的 `source_id`；
- 精确数值有明确证据，视觉印象不伪装成数值；
- 组件的可复用范围和禁止使用条件均可见；
- 待确认项写明对后续原型的影响。
